# Fused Map

Fused Map is a map widget in Fused. It draws geospatial data from a UDF, a SQL query, or a tile URL: points, polygons, H3 hexagons, and raster tiles, with many layers on one map.

Its type is `fused-map`. It works like any other [widget](/guide/data-input-outputs/import-connection/widgets): configure it in JSON, connect UDFs with edges, and share it as a URL. To see working examples, open the [Fused Map example canvas](https://www.fused.io/canvas/fc_fused/map_widget_canvas). For the props, see the [Fused Map API reference](/widget-api/fused-map).

## Add a Fused Map widget

1. In the Workbench canvas, select the **Widget** icon in the toolbar.
2. In the **Widget configuration** panel, select **Preset**, then **Maps and geo**, then **Fused map**.
3. Connect the UDF node to the widget node with an edge.
4. In the JSON, set `udf` to the name of the UDF in double braces, for example `{{my_udf}}`.

For a faster way, drag an edge from the output handle of a UDF node to an empty spot on the canvas, then select **Fused map** in the menu. Workbench creates a Fused Map widget that is already connected to the UDF and draws its result.

![Drag an edge from a UDF node and select Fused map](/img/widgets/fused-map-drag-node.gif)

:::note
The UDF must be on the same canvas. The name in `{{ }}` must match the UDF name exactly, with the same case.
:::

## Layer types and data sources

Fused Map has several layer types, set with each layer's `type`. Some common ones:

| `type` | Data |
|---|---|
| `geojson` | A GeoDataFrame, or rows with `lat` and `lng` columns (set `latColumn` and `lngColumn` for other names). |
| `h3` | A DataFrame with an H3 cell column. |
| `raster` | An image array. |
| `fused-hex` | A dataset [indexed with `fused.h3`](/guide/h3-analytics/data-retrieval-end-to-end), read with no UDF. |

For every layer type, see the [Fused Map API reference](/widget-api/fused-map). Other columns in the data become feature properties for tooltips, filters, and data-driven colors.

Each layer reads its data in one of these ways:

| Property | What the map does |
|---|---|
| `udf` | Runs the UDF one time and draws the whole result. |
| `udf` and `tile: true` | Runs the UDF for each map tile. The UDF gets the tile `bounds`. |
| `sql` | Runs a DuckDB query on a UDF result, then draws the rows. |
| `data: "{{name}}"` | Draws the rows a canvas SQL source published (an `h3-query` or `sql-runner` widget's `name`, or another map's layer id), read from DuckDB with no UDF run. Needs an edge from the publishing node to the map. A `sql` on the layer reads the rows as `{{source}}`. Row layers only: not with `tile`, `udf` or `tileUrl`, nor on `raster`, `mvt` or `fused-hex`. |
| `tileUrl` | Reads tiles from a URL with `{z}`, `{x}`, and `{y}` placeholders. |
| `source` (`fused-hex` only) | Queries the indexed dataset through [`GET /h3/query`](/rest-api/h3) for each map tile. |
| `sql` with `tile: true` or `fused-hex` | Runs the DuckDB query on each tile's rows as `{{source}}` as the tile loads, then draws the rows. `WHERE`, computed columns and `GROUP BY` the cell work per tile; `LIMIT`, `ORDER BY` and other UDFs do not apply. |

:::important Name the first argument `bounds` to load data per tile
With `tile: true`, the map passes each tile's area as `[west, south, east, north]` in `EPSG:4326`. Return only the rows inside `bounds`. The type doesn't matter, only the name.

```python
@fused.udf
def udf(bounds):
    ...
```
:::

| `tile` | First argument is `bounds` | Result |
|---|---|---|
| `true` | Yes | Each tile gets its own data. |
| `true` | No | Every tile gets the same result. |
| `false` | Either | The UDF runs once and `bounds` is ignored. |

To make a layer dynamic, pass a widget input's value to the UDF from the layer's `udf` in the Fused Map widget JSON. Write `{{my_udf?<udf_argument>=$<param>}}`, where `<param>` is the input's `param` name. For example, with an input whose `param` is `band`, `"udf": "{{my_udf?band_index=$band}}"` passes its value to the UDF's `band_index` argument and re-runs the UDF when it changes.

## Send map values to other widgets

A map can send its viewport bounds (`param`), the clicked feature (`clickParam`), the feature under the cursor (`hoverParam`), its box selection (`selectParam`) and its camera and layer state, saved with the canvas (`stateParam`), and a version per layer that changes when the layer's SQL rows change (`sourceParam`), to canvas parameters. Other widgets and UDFs read them as `$<name>`. `param` gets the map's real bounds once when the map is ready, then with `autoSend` on pans. These and the other options are in the [Fused Map API reference](/widget-api/fused-map).

The camera in `stateParam` is its `view`, `{centerLng, centerLat, zoom, bearing, pitch, width, height}`, with `width` and `height` the map canvas in CSS pixels. It updates only when a pan, zoom, rotate or tilt gesture ends, not while the map moves. A page can use it to place its own overlay on the map once the map has settled, converting between lng/lat and pixels from the map canvas's top-left corner with these (exact at `bearing` 0 and `pitch` 0), where `v` is the `view`:

```js
const R = Math.PI / 180;
const worldX = (lng) => (lng + 180) / 360;
const worldY = (lat) => 0.5 - Math.log(Math.tan(Math.PI / 4 + (lat * R) / 2)) / (2 * Math.PI);
function project(lng, lat, v) {
  const size = 512 * 2 ** v.zoom;
  return [(worldX(lng) - worldX(v.centerLng)) * size + v.width / 2, (worldY(lat) - worldY(v.centerLat)) * size + v.height / 2];
}
function unproject(x, y, v) {
  const size = 512 * 2 ** v.zoom;
  const wx = worldX(v.centerLng) + (x - v.width / 2) / size, wy = worldY(v.centerLat) + (y - v.height / 2) / size;
  return [wx * 360 - 180, (2 * Math.atan(Math.exp((0.5 - wy) * 2 * Math.PI)) - Math.PI / 2) / R];
}
```

<details>
<summary>Show the <code>bay_area_seismic_raster</code> UDF</summary>

The raster layer uses `tile: true`, so the first argument is `bounds`.

```python
@fused.udf
def udf(
    bounds: fused.types.Bounds = [-122.6, 37.2, -121.7, 38.0],
    path: str = "s3://fused-asset/demos/seismic_data/v2023_1_pga_475_rock_3min.tif",
):
    common = fused.load("https://github.com/fusedio/udfs/tree/fbf5682/public/common/")
    tile = common.get_tiles(bounds, zoom=common.estimate_zoom(bounds))
    arr = common.read_tiff(tile, input_tiff_path=path)
    return common.arr_to_plasma(arr.filled(0), min_max=(0, 1.5))
```

</details>

<details>
<summary>Show the <code>sf_listings</code> UDF</summary>

The points layer runs once and has no `bounds` argument.

```python
@fused.udf
def udf(path: str = "s3://fused-sample/demo_data/airbnb_listings_sf.parquet"):
    import geopandas as gpd
    import pandas as pd

    df = pd.read_parquet(path)
    df = df.dropna(subset=["latitude", "longitude", "price_in_dollar"])
    gdf = gpd.GeoDataFrame(
        df[["name", "neighbourhood_cleansed", "room_type", "price_in_dollar"]],
        geometry=gpd.points_from_xy(df["longitude"], df["latitude"]),
        crs="EPSG:4326",
    )
    return gdf
```

</details>

## The sidebar

The sidebar lets the viewer change the style, the filters, and the SQL of each layer in the browser. Each layer has a **Style** tab and a **Filters** tab. In **Style**, set the layer type, the fill mode (for example **By value** with a property, a palette, steps, and a domain), the stroke, and the opacity.

![The Fused Map sidebar next to the map and the widget configuration](/img/widgets/fused-map-sidebar.jpg)

These changes are temporary. To keep them, select **Save to widget** to write them into the widget configuration, or select **Copy config** and paste the result into the JSON. Select **Reset** to undo the changes.
