# Ingest, Index & Query H3 Datasets

`fused.h3` turns your data into a **hex dataset**: H3-sorted Parquet files you can query by point, bounding box, cell, time or partition value without scanning every file. It works for points, vector geometries, GeoTIFF / COG rasters, gridded weather data, and tables that already have an H3 column.

Every dataset goes through three steps:

1. **Partition**: [`fused.h3.partition()`](/python-sdk/api-reference/h3#partition) writes your rows as a hex dataset.
2. **Index**: [`fused.h3.index()`](/python-sdk/api-reference/h3#index) registers the dataset with Fused.
3. **Query**: [`fused.h3.query()`](/python-sdk/api-reference/h3#query) reads rows back as a DataFrame.

The examples below run all three steps on a small sample of a cloud-native dataset, so you can see the whole flow before running it at scale. Every parameter is described in the [`fused.h3` API reference](/python-sdk/api-reference/h3).

:::note
`fused.h3.partition()` must run inside a [UDF](/guide/working-with-udfs/writing-udfs). `index()` and `query()` work anywhere the `fused` SDK is authenticated.
:::

## Things to know

- **Every row needs a location.** Pass `point_column=("lat", "lng")` for latitude/longitude columns, or `point_column="geometry"` for a geometry column (shapes use their centroid; polygons are not polyfilled). If rows already carry an H3 cell, pass `hex_column` instead. Coordinates must be in EPSG:4326.
- **Gridded data can fill every cell.** With `fill="nearest"`, each hex gets the values of its nearest grid point, so a coarse grid still covers every cell at a finer resolution.
- **Folders are for filters, not for space.** Rows are already sorted by hex, so spatial queries are fast. Use `partition_by` for what you filter or reload by, such as `date`.
- **Indexing is a batch job.** It takes about a minute for small data. Re-running only indexes new files; pass `overwrite=True` after rewriting a dataset with different settings, such as a new `h3_res`.
- **Queries take one spatial selector** (`cell`, `lat`/`lng`, `bbox` or `hex_range`) plus optional time and partition filters. A query reads at most 1,024 row groups by default; if it fails with a 413, narrow it.

## Examples

### Example: NYC 311 points

[Open this example in Canvas →](https://www.fused.io/canvas/fc_fused/H3_End_to_End_Ingestion?bounds=-20,-20,3975,660)

Count NYC 311 noise complaints per hex. The NYC Open Data API filters on the server, so only one week of complaints (about 16,000 rows) is downloaded. Each complaint has a latitude and longitude, so `partition()` uses `point_column`, and `partition_by="date"` writes one folder per day. Convert `created_date` to a date rather than a string: `date` then becomes the time column, and `time_min` / `time_max` work in queries.

<details>
<summary>Code</summary>

```python showLineNumbers {17-20,23-24}
@fused.udf(cache_max_age=0)
def udf(out: str = "fd://h3/nyc311_noise/"):
    import pandas as pd
    from urllib.parse import urlencode

    # 1. One week of 311 noise complaints. The NYC Open Data API filters on the server.
    query = urlencode({
        "$select": "unique_key, created_date, complaint_type, latitude, longitude",
        "$where": "created_date between '2024-07-01T00:00:00' and '2024-07-07T23:59:59'"
                  " AND complaint_type like 'Noise%' AND latitude IS NOT NULL",
        "$limit": 200000,
    })
    df = pd.read_csv(f"https://data.cityofnewyork.us/resource/erm2-nwe9.csv?{query}")
    df["date"] = pd.to_datetime(df.pop("created_date")).dt.date

    # 2. Partition: res-11 hexes, one folder per day
    fused.h3.partition(
        df, out, point_column=("latitude", "longitude"),
        h3_res=11, file_res=5, partition_by="date", overwrite=True,
    )

    # 3. Index, then 4. query July 4 in lower Manhattan
    fused.h3.index(out, overwrite=True)
    return fused.h3.query(out, bbox=(-74.02, 40.70, -73.97, 40.75), partition={"date": "2024-07-04"})
```

</details>

The query returns the 435 complaints from July 4 inside the lower Manhattan box. To scale up, fetch one day per worker with [`.map()`](/guide/working-with-udfs/fused-submit), write each day to Parquet, then partition the whole folder in one call with `fused.h3.sources.parquet()`.

### Example: GeoTIFF raster

[Open this example in Canvas →](https://www.fused.io/canvas/fc_fused/H3_End_to_End_Ingestion?bounds=-20,780,3975,1460)

Average elevation per hex from a Cloud-Optimized GeoTIFF (COG). `partition()` works on rows, so the raster becomes rows first: read a window of the Copernicus DEM (only that part is downloaded), turn each 30 m pixel into a lat/lng point, and average the pixels in each hex with DuckDB's `h3_latlng_to_cell()`. The rows then already have a hex, so `partition()` uses `hex_column`. This COG is in EPSG:4326; for a raster in a projected CRS, transform the pixel coordinates to latitude/longitude first.

<details>
<summary>Code</summary>

```python showLineNumbers {31-33}
@fused.udf(cache_max_age=0)
def udf(out: str = "fd://h3/nyc_elevation/", h3_res: int = 10):
    import numpy as np
    import pandas as pd
    import rasterio
    from rasterio.windows import from_bounds

    # 1. Read only an NYC window of the Copernicus DEM, a 30 m Cloud-Optimized GeoTIFF on AWS
    cog = (
        "https://copernicus-dem-30m.s3.eu-central-1.amazonaws.com/"
        "Copernicus_DSM_COG_10_N40_00_W074_00_DEM/Copernicus_DSM_COG_10_N40_00_W074_00_DEM.tif"
    )
    with rasterio.open(cog) as ds:
        window = from_bounds(-74.0, 40.6, -73.75, 40.9, transform=ds.transform)
        band = ds.read(1, window=window)
        transform = ds.window_transform(window)
    rows, cols = np.indices(band.shape).reshape(2, -1)
    lng, lat = rasterio.transform.xy(transform, rows, cols)  # EPSG:4326 already
    pixels = pd.DataFrame({"lat": lat, "lng": lng, "elevation": band[rows, cols].astype("float64")})

    # 2. Average the pixels inside each hex
    common = fused.load("https://github.com/fusedio/udfs/tree/b6786d6/public/common/")
    con = common.duckdb_connect()
    df = con.sql(f"""
        SELECT h3_latlng_to_cell(lat, lng, {h3_res})::UBIGINT AS hex,
               AVG(elevation) AS elevation, COUNT(*) AS pixels
        FROM pixels GROUP BY 1
    """).df()

    # 3. Partition, index, then 4. query the hex containing Central Park
    fused.h3.partition(df, out, hex_column="hex", h3_res=h3_res, file_res=5, overwrite=True)
    fused.h3.index(out, overwrite=True)
    return fused.h3.query(out, lat=40.7829, lng=-73.9654)
```

</details>

The window's 972,000 pixels become 46,862 res-10 hexes; the Central Park hex averages 22 pixels. To scale up, split the area into tiles (or one per COG), run the pixel-to-hex step on each tile with [`.map()`](/guide/working-with-udfs/fused-submit), write each tile to Parquet, then partition the folder with `fused.h3.sources.parquet()`.

### Example: ERA5 weather

[Open this example in Canvas →](https://www.fused.io/canvas/fc_fused/H3_End_to_End_Ingestion?bounds=-20,1580,3975,2260)

Daily weather per hex. For `fill="nearest"`, gridded data has to be lat/lng rows with a complete grid for each date. [`fused.h3.sources.era5()`](/python-sdk/api-reference/h3#sourcesera5) reads ERA5 from Google's public ARCO ERA5 Zarr store and returns exactly that shape (the Source node in the canvas). `fill="nearest"` then gives every res-6 hex the values of its nearest 0.25° grid point. Keep measurements as floats: with `fill="nearest"`, non-float columns are treated as keys, like `date`.

<details>
<summary>Code</summary>

```python showLineNumbers {5,8-17,20-21}
@fused.udf(cache_max_age=0)
def udf(out: str = "fd://h3/era5_nyc_1day/"):
    # 1. One day of ERA5 around New York (July 4, 2024)
    bbox = (-76.5, 39.5, -71.5, 42.5)  # (min_lng, min_lat, max_lng, max_lat)
    batches = fused.h3.sources.era5(2024, 7, outputs=["t2m_max", "tp"], days=[4], bbox=bbox)

    # 2. Partition: every res-6 hex gets its nearest grid point's values
    fused.h3.partition(
        batches,
        out,
        point_column=("lat", "lng"),
        fill="nearest",
        h3_res=6,
        file_res=2,
        partition_by="date",
        overwrite=True,
    )

    # 3. Index, then 4. query the cell containing New York City
    fused.h3.index(out, overwrite=True)
    return fused.h3.query(out, lat=40.7128, lng=-74.0060)
```

</details>

One day's 273 grid points fill 4,368 hexes around New York; the query returns the New York cell's `t2m_max` (daily maximum 2 m temperature, Kelvin) and `tp` (total precipitation, mm). To scale up, read whole months without `days` and `bbox`, chain several months of `sources.era5()` batches (for example with `itertools.chain`) into one `partition()` call, and run the UDF with `engine="large"`.
