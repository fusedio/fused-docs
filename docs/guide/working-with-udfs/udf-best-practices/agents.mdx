Once you've written a UDF, any AI agent can call it as a tool. Connect its canvas to the agent, then follow the checklist below so the agent picks the right UDF and gets a small, precise answer back.

## Connect a canvas to an agent

From the CLI, share the canvas once, then add it to Claude Code:

```bash
fused workbench canvas share <canvas_name>
fused workbench claude add-mcp <canvas_name>
```

Other MCP clients like Cursor or VS Code take the canvas MCP URL, `https://udf.ai/<fc_token>.mcp`, where `<fc_token>` is the `share_token` that `canvas share` prints.

From the UI, open the canvas in Workbench or [Fused Render](/workbench/fused-render) and click **Share → Copy MCP**. See [Connect canvases to AI](/guide/data-input-outputs/import-connection/ai-data-connection) for Claude Desktop, claude.ai and the AI chat widget.

## Checklist

| Do this | Why |
|---|---|
| Name the tool with a comment on the first line, like `# get_county_population`. The function stays `udf`. | Agents choose tools by name. |
| Write a docstring that says what the UDF answers and when to use it. | The docstring is the tool description. |
| Use descriptive parameter names (`region_fips`, not `r`) and give every parameter a default. | The agent doesn't have to guess. |
| Return a small summary and add a `top_n` or `limit` parameter. | Large results flood the agent's context. |
| Precompute and read from storage, and cache setup with [`@fused.cache`](/guide/working-with-udfs/udf-best-practices/caching). | Every call blocks the agent, and UDFs time out after [120s](/guide/working-with-udfs/udf-best-practices/realtime#limits). |
| Take S3 or GCS paths as input, not file contents. | Keeps calls small. |
| Add `output_path` and `save_to_file` parameters to UDFs that transform data. | The next UDF reads the saved path, so agents can chain calls. |
| Name output columns after what they contain. | A count in a column called `latitude` misleads the agent. |
| Hide helper UDFs, and keep agent-facing UDFs on their own canvas. | Only visible UDFs become tools, and the whole canvas shares one token. |

:::warning Don't block on long jobs
A UDF that waits for a 5-minute job burns compute and hits the 120s timeout. Start the job, return a job ID, and add a separate status UDF. See [Scaling out UDFs](/guide/working-with-udfs/udf-best-practices/scaling-out).
:::

:::warning Treat every parameter as untrusted
Never accept free-form SQL or table names, only read paths under a prefix you hardcode, never expose credentials as parameters, and constrain inputs with an allowlist. See [Write UDFs securely](/guide/working-with-udfs/udf-best-practices/security).
:::

<details>
<summary>Return a summary</summary>

```python
# get_top_counties_by_population

@fused.udf
def udf(state: str = "CA", top_n: int = 10):
    """
    Returns the top N counties by population for a given state.
    """
    import pandas as pd
    df = pd.read_parquet("s3://my-bucket/census/raw.parquet")
    return (
        df[df["state"] == state]
        .groupby("county")["population"]
        .sum()
        .nlargest(top_n)
        .reset_index()
    )
```

</details>

<details>
<summary>Start a long job</summary>

```python
# trigger_census_ingestion

@fused.udf
def udf(dataset: str = "census_2023", region: str = "CA"):
    """
    Starts a batch ingestion job for the dataset and region and returns its job ID.
    Use check_ingestion_status with the job ID to monitor progress.
    """
    import uuid
    job_id = str(uuid.uuid4())
    enqueue_batch_job(dataset=dataset, region=region, job_id=job_id)
    return {"job_id": job_id, "status": "queued"}
```

</details>

<details>
<summary>Chain through a saved file</summary>

```python
# transform_data

@fused.udf
def udf(path: str, output_path: str = "", save_to_file: bool = False):
    """
    Transforms the dataset at path. With save_to_file=true, writes the
    result to output_path and returns the path for the next UDF.
    """
    gdf = process(path)
    if save_to_file and output_path:
        gdf.to_parquet(output_path)
        return {"status": "success", "output_path": output_path, "rows": len(gdf)}
    return gdf
```

</details>
