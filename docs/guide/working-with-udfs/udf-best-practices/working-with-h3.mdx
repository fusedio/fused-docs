# Working with H3

[H3](https://h3geo.org/) is a hexagonal global grid system. It's a good fit when you need to:
- Build heatmaps of events (populations, counts, etc.)
- Compare datasets across resolutions and scale
- Work with sparse datasets, like point or location data

You can try all of the basics of H3 on this [Canvas →](https://www.fused.io/canvas/fc_public/Basics_of_H3_in_Fused)

A typical H3 workflow has four stages: **convert** your source data into hexagons, **pick a resolution** that fits your data and use case, **aggregate** to make the data useful at different zoom levels, and **join** it with other H3 datasets for analysis.

## 1. Convert your data to H3

How you convert depends on your data's type and size:

| Data | Size | Approach | API |
|------|------|----------|-----|
| Point / vector (CSV, GeoJSON, Parquet) | Small (< 100MB) | On the fly, per-request | [`h3_latlng_to_cell()` via DuckDB](/guide/h3-analytics/converting#file-to-h3) |
| Vector polygons | Small or large | On the fly, per viewport (Tile UDF mode) | [`common.gdf_to_hex()`](/guide/h3-analytics/converting#dynamic-tile-to-h3) |
| Points, geometries, or a table with an H3 column | Large (> 100k rows) | Pre-computed: partition, index, query | [`fused.h3.partition(point_column=...)`](/python-sdk/api-reference/h3#partition) or `hex_column=...`, then [`index()`](/python-sdk/api-reference/h3#index) and [`query()`](/python-sdk/api-reference/h3#query). See [NYC 311 example](/guide/h3-analytics/hex-datasets#example-nyc-311-points) |
| Raster (GeoTIFF, COG) | Large (> 100MB) | Pre-computed: pixels averaged per hex, then partitioned | [`fused.h3.partition(hex_column="hex")`](/python-sdk/api-reference/h3#partition), then [`index()`](/python-sdk/api-reference/h3#index) and [`query()`](/python-sdk/api-reference/h3#query). See [GeoTIFF example](/guide/h3-analytics/hex-datasets#example-geotiff-raster) |
| Gridded raster on a regular lat/lng grid (e.g. ERA5 weather) | Large | Pre-computed: every cell filled from the nearest grid point | [`fused.h3.partition(fill="nearest")`](/python-sdk/api-reference/h3#partition), then [`index()`](/python-sdk/api-reference/h3#index) and [`query()`](/python-sdk/api-reference/h3#query). See [ERA5 example](/guide/h3-analytics/hex-datasets#example-era5-weather) |

Small datasets can be hexagonified on the fly inside a single UDF. Large datasets are better pre-computed once: **partition** them into a hex dataset with `fused.h3.partition()`, **index** it with `fused.h3.index()`, then **query** it by point, bounding box, cell, time or partition value with `fused.h3.query()`. This avoids re-processing the same data on every request. See [Ingest, Index & Query](/guide/h3-analytics/hex-datasets).

To see the whole flow on a small sample, open the end-to-end examples in Canvas: [points (NYC 311)](https://www.fused.io/canvas/fc_fused/H3_End_to_End_Ingestion?bounds=-20,-20,3975,680), [raster (NYC elevation)](https://www.fused.io/canvas/fc_fused/H3_End_to_End_Ingestion?bounds=-20,780,3975,1480) and [gridded weather (one day of ERA5)](https://www.fused.io/canvas/fc_fused/H3_End_to_End_Ingestion?bounds=-20,1580,3975,2280).

:::warning Deprecated ingestion APIs
[`fused.h3.run_ingest_raster_to_h3()`](/python-sdk/api-reference/h3#run_ingest_raster_to_h3) and [`run_partition_to_h3()`](/python-sdk/api-reference/h3#run_partition_to_h3) are deprecated. They still work for existing datasets; use `fused.h3.partition()` for new ones.
:::

If your dataset doesn't fit the patterns above (hundreds of GB, tens of thousands of files, or a custom ingestion shape), reach out to **info@fused.io** — we can help you scale the ingestion or point you to the right [execution engine](/python-sdk/api-reference/udf#map).
:::

## 2. Pick a resolution

The resolution (`res`) controls hex size, and it drives everything downstream — conversion fidelity, how much data you store, and the granularity available for aggregation and joins. By default, resolution is inferred from the input (e.g. raster pixel size), but you can set it explicitly.

| Resolution | Avg edge length | Typical use case |
|------------|-----------------|-------------------|
| 3 | 59.81 km | Regional |
| 7 | 1.22 km | Neighborhood |
| 9 | 174.38 m | Block |
| 12 | 10.8 m | Building |

See the [Resolution Guide](/guide/h3-analytics/resolution-guide) for the full table and how Fused infers resolution from raster pixel size.

## 3. Aggregate

Resolution and aggregation go hand in hand: once data is in H3 at a base resolution, you aggregate it up to coarser (parent) resolutions to make it fast to render and analyze at different zoom levels. Aggregation is also the precursor to joining: two datasets need to share a resolution before they can be joined cell-by-cell.

How you aggregate depends on the data type:
- **Numerical** (temperature, elevation, population): sum, mean, max, min, or stddev per cell.
- **Categorical** (land use, crop type): count occurrences, or take the mode, per cell.

You can also derive new layers from aggregated data — e.g. computing slope from an elevation layer using neighboring cells (`h3_grid_ring`).

See [Aggregations](/guide/h3-analytics/aggregations) for the full examples.

## 4. Join datasets

Once two H3 datasets share the same `hex` column and resolution, merging them is a standard SQL join (via DuckDB) on `hex` — no spatial join needed. This is the easiest way to combine datasets that would otherwise be hard to merge directly, such as:
- Datasets in different spatial projections
- Sparse datasets like location data
- Datasets at different native resolutions or of different types (raster + vector)

See [Joining](/guide/h3-analytics/joining) for a worked example merging an elevation layer with a crop-type layer.

## 5. Visualize

Once your H3 data is converted, aggregated, and (optionally) joined, you have two options to render it as hexagons:
- **Workbench Map Viewer**: style it directly as a vector `H3HexagonLayer`, with or without tiles.
- **Canvas**: combine UDFs into an interactive visualization.

For more detail, see [Visualization](/guide/h3-analytics/visualization).
