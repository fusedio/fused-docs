## delete_index

```python
delete_index(
    path: str,
    *,
    prefix: str | list[str] | None = None,
    base_url: str | None = None
) -> dict[str, Any]
```

Delete the index registered for `path`, or with `prefix` only the
part of it under those folders. The data files are untouched.

**Parameters:**

- **path** (`str`) – The location an earlier `fused.h3.index` call registered.
- **prefix** (`str | list[str] | None`) – Optional. A folder under `path` (relative to it, such as
  `"month=1940-01"`, or spelled in full), or a list of them. Only
  what is indexed under those folders is deleted; the location
  keeps serving the rest. Folders are cleared one at a time, so a
  call that is interrupted leaves each folder either fully removed
  or intact, and calling again finishes the rest. A later
  `fused.h3.index` run that still lists those files indexes them
  again. Without `prefix` the whole index is deleted, location
  included.
- **base_url** (`str | None`) – Base URL for the API. If None, uses the current environment.

**Returns:**

- `dict[str, Any]` – A dictionary with the resolved `path`, and for a scoped delete
- `dict[str, Any]` – the full `prefix` paths, the `count` of index rows deleted and the
- `dict[str, Any]` – number of `folders` cleared.

## index

```python
index(
    path: str,
    hex_column: str = "hex",
    time_column: str | None = None,
    *,
    partition_columns: str | list[str] | None = None,
    engine: InstanceType | Literal["realtime"] = "realtime",
    overwrite: bool = False,
    prefix: str | list[str] | None = None,
    workers: int | None = None,
    force: bool = False,
    visibility: str | None = None,
    base_url: str | None = None
) -> TaskRun
```

Register a hive-partitioned parquet tree as a queryable H3 location.

Asks the server to walk `path` and build its row-group index. By default
the run is a realtime run, which starts at once and is limited to a few
minutes; pass a batch `engine` for a large tree. Returns as soon as the
run has started; follow it with `run.tail()` or `index_status`. The index
belongs to your team, which alone can re-index it; each team holds its
own index of a path. See `visibility` and `fused.h3.set_visibility` for
sharing it.

**Parameters:**

- **path** (`str`) – Path to the parquet tree (e.g. `"s3://my-bucket/my-dataset/"`).
  Every `.parquet` file under it, at any depth, must carry an
  integer H3 cell column named `hex_column` at a single resolution.
- **hex_column** (`str`) – Name of the H3 cell column present in every file.
  Defaults to `"hex"`, what `fused.h3.partition` writes.
- **time_column** (`str | None`) – Optional. Names either an in-file timestamp/date column,
  or a folder level written `key=value` whose value is a `YYYY`,
  `YYYY-MM`, or `YYYY-MM-DD` period covering every row under that
  folder, or an ISO timestamp (an instant). If None, the only `date` partition column filters by time,
  and a location without one is timeless.
- **partition_columns** (`str | list[str] | None`) – The `key=value` folder levels (e.g.
  `scenario=ssp245/date=2050-01/`) whose values `query` can filter
  by, as a column name or a list of names in folder order. Defaults
  to the `partition_by` columns in the tree's `_manifest.json`
  (written by `fused.h3.partition`), else none. Each column is typed
  `"string"`, `"number"` or `"date"` from the manifest, else from
  its values (all numbers: number; all `YYYY`, `YYYY-MM`,
  `YYYY-MM-DD` periods or ISO instants: date; otherwise string). Each
  leaf folder must have exactly one folder per column, in that
  order; a folder that does not fails the run.
- **engine** (`InstanceType | Literal['realtime']`) – Where the run happens. `"realtime"` (the default) runs
  on the realtime tier: no instance to wait for, but limited to a
  few minutes. A batch instance type or alias (`"small"`,
  `"medium"`, `"large"`, ...) runs as a batch job with no time
  limit. Never falls back from one to the other.
- **overwrite** (`bool`) – If False (the default), re-running is incremental: folders
  unchanged since the last run are skipped, and only new, changed
  and removed files are indexed or dropped. A run that was stopped
  or partly failed resumes where it left off. If True, the whole
  tree is indexed again from scratch, replacing the previous index.
- **prefix** (`str | list[str] | None`) – Optional. A folder under `path` (relative to it, such as
  `"month=2026-10"`, or spelled in full), or a list of such
  folders, that limits the run to those folders: only they are
  listed and indexed, and only files and folders under them can be
  dropped as gone. The rest of the location is neither read nor
  touched, so adding one partition to a large archive costs that
  partition rather than a walk of the whole tree, and a list of
  partitions (a year's months, say) costs those in one run. The
  location is still the whole tree at `path`, served from every
  folder any run has indexed, and a scoped run may be its first.
  Cannot be combined with `overwrite`.
- **force** (`bool`) – Optional. Read every file under the scope again, unchanged
  folders included: each folder's old rows are dropped and
  replaced within the same generation, so the location keeps
  serving throughout and nothing outside the scope is touched.
  This is how to redo part of a large location when the files on
  disk are fine but what was indexed from them is not (an
  extractor bug, say) -- `overwrite` would redo the whole tree.
  It does not change the location's columns; that still needs
  `overwrite`. Default False.
- **workers** (`int | None`) – Optional. How many files the job reads at once; defaults
  to 32. Reading is bound by object-store round trips, so a larger
  instance can take more -- 128 measured at roughly twice the
  throughput of 32.
- **visibility** (`str | None`) – `"team"` or `"public"` (Fused admins only); None keeps
  the location's current visibility (`"team"` for a new one).
- **base_url** (`str | None`) – Base URL for the API. If None, uses the current environment.

**Returns:**

- `TaskRun` – The `TaskRun` of the indexing run, returned as soon as it has started.
- `TaskRun` – `run.tail()` prints its log lines until it finishes (and its error if
- `TaskRun` – it failed), `run.status()`, `run.done()` and `run.logs()` poll it, and
- `TaskRun` – `index_status(path)` reports the index once the run has succeeded. If
- `TaskRun` – only some files fail to index, everything else is indexed and
- `TaskRun` – queryable; the run's error names the failed paths, and re-running
- `TaskRun` – retries them. A realtime run that runs out of time fails; retry with a
- `TaskRun` – batch `engine`.

**Example:**

````python
```py
fused.h3.index(
    path="s3://my-bucket/era5_h3/",
    hex_column="hex",
    partition_columns=["scenario", "date"],
)
# Later, after writing one more month:
fused.h3.index("s3://my-bucket/era5_h3/", prefix="date=2050-02")
# Or a year's worth of months in one run:
fused.h3.index(
    "s3://my-bucket/era5_h3/",
    prefix=[f"date=2051-{m:02d}" for m in range(1, 13)],
)
````

## partition

```python
partition(
    data: Any,
    output: str | Path,
    *,
    hex_column: str | None = None,
    point_column: str | tuple[str, str] | None = None,
    h3_res: int = 7,
    file_res: int = 1,
    fill: str | None = None,
    partition_by: str | list[str] | None = None,
    sort_by: str | list[str] | None = None,
    overwrite: bool = False,
    append: bool = False,
    row_group_size: int = 65536,
    compression: str = "zstd",
    compression_level: int = 5,
    key_columns: list[str] | None = None,
    memory_budget: int = 2 << 30,
    workers: int | None = None,
    parts: list[dict[str, Any]] | None = None,
    only: list[str] | None = None,
    force: bool = False,
    refresh: bool = False,
    read_engine: InstanceType = "small",
    engine: InstanceType | Literal["realtime"] = "small",
    base_url: str | None = None
) -> Run
```

Write data as hex-sorted H3 parquet files with a `_manifest.json`.

The work runs on the Fused server. A `udf` or `era5` source is first
read by an `h3.read` batch job per part on `read_engine`, which caches
the rows as parquet inside `output`; the `h3.partition` task then
writes the files, on the batch instance by default (no time limit) or on
the realtime tier (a few minutes at most) when `engine="realtime"` (not
for a `udf` or `era5` source). Returns as soon as the run has started.

**Example:**

```python
An ERA5 year, one part per month, read on a large instance::

    fused.h3.partition(
        fused.h3.sources.era5(outputs=["t2m_mean"]),
        "fd://me/era5_2024/",
        parts=[{"month": f"2024-{m:02d}"} for m in range(1, 13)],
        partition_by=["month"],
        point_column=("lat", "lng"), fill="nearest",
        read_engine="large",
    )

A UDF that returns your data, in one pass::

    @fused.udf
    def load():
        import pandas as pd
        return pd.read_csv("https://example.com/points.csv")

    fused.h3.partition(
        fused.h3.sources.udf(load), "fd://me/points/",
        point_column=("lat", "lng"),
    )
```

**Parameters:**

- **data** (`Any`) – What to partition: a `fused.h3.sources` source or a `str` or
  path-like on `s3://`, `gs://`, `gcs://` or `fd://`, which is
  read like `fused.h3.sources.parquet(path)`. It is sent to the
  server as a description; nothing is read or uploaded from this
  machine. A `sources.udf` source runs your UDF on the engine,
  which must return the part's rows (see `fused.h3.sources.udf`);
  to partition data you have in Python, return it from a UDF. A
  DataFrame, Table, RecordBatch, local, `memory://` or `az://`
  path or any other type raises `TypeError`.
- **output** (`str | Path`) – Output folder on `fd://` or a cloud URL (`s3://`,
  `gs://`); a local path or an Azure URL (`az://`) is not
  supported because the task runs on the server, which writes
  only to storage it has access rules for. Files are written as
  `<output>/<col>=<value>/.../<H3 parent cell hex>.parquet`, one
  `col=value` folder per `partition_by` column in that order
  (for example `scenario=ssp245/date=2050-01-01/`), or
  `<output>/<H3 parent cell hex>.parquet` when there is no `partition_by`.
- **hex_column** (`str | None`) – Name of an existing H3 cell column (uint64). Give exactly
  one of `hex_column` and `point_column`.
- **point_column** (`str | tuple[str, str] | None`) – Where each row is, so the cell at `h3_res` can be computed.
  Either `("lat_column", "lng_column")`, two numeric columns (lat
  first), or the name of one geometry column holding WKB (`binary`),
  such as `point_column="geometry"`. A Point geometry hexes itself; any
  other geometry gets the cell covering its centroid. Nothing is
  polyfilled: one row in, one row out. Null and empty geometries
  raise. The centroid is planar, taken on the coordinates as stored,
  which must be lon/lat degrees (EPSG:4326); a centroid outside lon
  -180..180 / lat -90..90 (for example projected coordinates)
  raises. Geometries that cross the antimeridian or wrap a pole get
  a centroid on the wrong side, so split them or pass lat/lng
  columns for those rows. Two lat/lng columns must be degrees too:
  nothing is reprojected, and projected values (UTM metres, say)
  raise. The point columns stay in the files. A
  `geopandas.GeoDataFrame` returned by a `sources.udf` UDF arrives
  with its geometry as WKB, and GeoParquet read with
  `fused.h3.sources.parquet` is already WKB.
- **h3_res** (`int`) – Resolution of the cell each row gets; this is the `hex`
  column, the key queries select rows by. With `point_column` the
  coordinate columns stay in the files, so every row keeps its exact
  position whatever `h3_res` is.
- **file_res** (`int`) – Resolution of the H3 parent cell that groups rows into
  files: each row's cell is walked up to its ancestor at this
  resolution and all rows under one ancestor are written to one
  file named after it (default 1, about 117k res-7 cells per file;
  raise it for more, smaller files).
- **fill** (`str | None`) – `"nearest"` fills every cell at `h3_res` from the nearest point
  of a regular lat/lng raster, instead of hexing each row as it is
  (the default). Each input batch must then hold a complete raster
  per key tuple, one row per raster point, as
  `fused.h3.sources.era5` yields. Key columns are `key_columns`,
  `partition_by` and every column that is not floating point (such
  as `date` or `hour`); the floating point columns are the values
  to fill, and none is an error. Needs `point_column=("lat", "lng")`. One
  filled batch becomes one batch per H3 parent cell.
- **partition_by** (`str | list[str] | None`) – Column, or list of columns, whose values become nested
  `col=value` folders. The default, None, is no folders without
  `parts`, and the columns the parts are split by with it (it
  must then be exactly those; see Parts below). Values
  are written by type: dates as `YYYY-MM-DD`, timestamps as ISO 8601
  (`2050-01-01T06:00:00`), integers as plain digits, floats and
  strings as they print. The type of each column is recorded in
  `_manifest.json`. Values may not be null, empty, start with `_` or
  contain `/`. The columns stay in the files.
- **sort_by** (`str | list[str] | None`) – Extra column(s) to sort by after `hex`.
- **overwrite** (`bool`) – Replace existing output. Without it, an any existing
  file in `output` (a dataset, or leftovers of an aborted run
  that has no `_manifest.json`) raises.
- **append** (`bool`) – Add to an existing partitioned dataset instead of failing on it.
  Every leaf partition folder this run writes replaces that folder
  in `output` (so re-running a day is idempotent) and the other
  folders are left alone; `_manifest.json` is updated to match.
  Needs `partition_by` and an existing `_manifest.json` whose
  `h3_res`, `file_res`, `fill`, `partition_by`, `sort_by`
  and partition column types match this call, checked before
  anything is written. Cannot be combined with `overwrite`. A run
  that dies midway leaves the folders it already replaced rewritten
  only in part, and the manifest unchanged, until it is run again.
- **row_group_size** (`int`) – Rows per parquet row group.
- **compression** (`str`) – Parquet compression codec.
- **compression_level** (`int`) – Compression level (zstd only).
- **key_columns** (`list[str] | None`) – Columns that get dictionary encoding (`hex` never
  does). Defaults to the `partition_by` columns when set, else none; name
  other low-cardinality columns here. With `fill="nearest"` the
  non-floating columns are added automatically.
- **memory_budget** (`int`) – Bytes of input rows held in memory while waiting for
  their file to be complete (default 2 GiB). Past it the buffered
  rows of every file are spilled to a hidden folder inside `output`.
  It counts buffered rows only: the source batch being processed, the
  fill cube and the per-file split of a batch are on top of it, so do
  not set it to the worker's RAM. Reading the input pauses while a
  spill is written, so on a machine with memory to spare, raise it
  until nothing spills.
- **workers** (`int | None`) – Threads that write the files once the input has ended.
  Defaults to 32 for object-store output and
  `min(32, os.cpu_count())` for local output. Each one holds a
  whole output file in memory while it writes it, so with large
  files (around 1 GB or more) use fewer, such as 2 to 4, or a
  machine with more memory.
- **parts** (`list[dict[str, Any]] | None`) – One dict of inputs per part, bound on `data` (see Parts
  below): `[{"month": "2024-01"}, {"month": "2024-02"}]` for
  `sources.era5`, a UDF's parameters for `sources.udf`, hive
  keys for `sources.parquet` (`{"state": "TX"}` reads
  `<path>/state=TX/`). Every dict has the same keys, which become
  the partition columns. Each part is its own read job and
  partition job, launched together in one call; jobs over your batch
  quota wait as `pending` instead of failing. Without `parts` the
  source runs as one part, with the inputs it was made with.
- **only** (`list[str] | None`) – Names of the parts (their ids, each input joined as
  `key=value`, such as `month=2024-01`) to run; the others are
  left alone. An unknown name raises, listing the available ones.
  Needs `parts`.
- **force** (`bool`) – Redo parts that are already marked done. Without it a part
  whose done marker (`_parts/<name>.json` in `output`) exists is
  skipped. Needs `parts`.
- **refresh** (`bool`) – Read a `udf` or `era5` part again. Without it a part whose
  rows are already cached in `<output>/.fused-h3-source/` (same
  source, inputs and code) is not read again. The cache is never
  deleted. Not for a `parquet` source, which has no read step.
- **read_engine** (`InstanceType`) – The batch instance type of the read jobs of a `udf` or
  `era5` source, `"small"` by default; `"medium"`,
  `"large"`, ... for a UDF or a month of ERA5 that needs more
  memory. Reading is always a batch job, so `"realtime"` raises.
  Unused for a `parquet` source.
- **engine** (`InstanceType | Literal['realtime']`) – `"small"` (the default) runs the partition job as a batch
  job with no time limit. `"realtime"` runs on the realtime tier
  and is limited to a few minutes, so it suits small parquet inputs;
  a `udf` or `era5` source raises with it. Other batch aliases or
  instance types (`"medium"`, `"large"`, ...) run as a batch
  job on a bigger instance.
- **base_url** (`str | None`) – Fused API base URL; defaults to the configured one.

**Returns:**

- `Run` – A `Run`, returned as soon as the jobs have started. `run.tail()`
- `Run` – follows it, printing each part's log lines as `[part] ...` and the
- `Run` – error of a part that failed; `run.status()` is `"failed"` if any
- `Run` – part failed, else `"succeeded"` if all did, else `"running"` or
- `Run` – `"pending"`; `run.parts()`, `run.errors()`, `run.failed()`,
- `Run` – `run.succeeded()` and `run.skipped()` say how each part went;
- `Run` – `run.retry()` runs the failed parts again, and
- `Run` – `fused.h3.get_run(run.id)` brings the run back in a new session.

Parts: with `parts=` the run appends to `output` (`append` is
implied, `overwrite` is refused: delete the output first, or pass
`force=True` to redo parts), writes the same `<hex>.parquet` files as
one run would, and, last, a done marker `_parts/<part>.json`. A part is
only a unit of work: every `partition_by` folder belongs to exactly one
part, so the output has one file per folder and parent cell however the
input was split. Each part therefore covers the columns named by its
inputs (`month` for an ERA5 month, `state` for a `state=TX`
subfolder, a UDF's parameters, which the UDF must return as columns with
those values). An empty `partition_by` becomes those columns, and a
`partition_by` that is not exactly them raises before anything starts,
as does an input still missing, a name the source does not accept, dicts
with different keys, two parts with one id, or a hive subfolder that does
not exist. A part that finds a folder already claimed by another part
fails without writing. Parts of one output run side by side; one part cannot
run twice at once. A part that died midway has no marker and is cleaned up
and redone by the next run; one with a marker is skipped unless
`force=True`. Without `parts` the source is one plain pass.

**Raises:**

- `TypeError` – `data` is not a source or a path the server can read: a
  DataFrame, Table or RecordBatch, a local, `memory://` or `az://`
  path (as a `str` or inside `sources.parquet`), an iterator of
  record batches or another unsupported type. Return the data from a
  UDF and pass `fused.h3.sources.udf(it)` instead.
- `ValueError` – An inconsistent argument or a local or Azure `output`.
  The task checks the rest on the server and fails the run (see
  `run.tail()`) for a named column missing from the source, an
  existing output without `overwrite` or `append`, `append`
  without an existing manifest or with settings that differ from it,
  or a problem found while bucketing (null or NaN coordinates, lat/lng
  outside lat -90..90 / lon -180..180 such as projected coordinates,
  null hex, null or folder-unsafe partition values).

Rows are buffered per output file in memory, up to `memory_budget`; past
it they are spilled to a hidden temporary folder inside `output`, removed
when the run ends. `overwrite=True` also removes such folders left behind
by a killed run. Readers may yield any mix of parent cells in any order.
Large batches are cheaper than many small ones.

A failed run never wipes a good dataset: existing output is only replaced
once the whole input has been read without error.

## query

```python
query(
    path: str,
    cell: str | None = None,
    *,
    lat: float | None = None,
    lng: float | None = None,
    bbox: tuple[float, float, float, float] | None = None,
    hex_range: tuple[str, str] | None = None,
    time_min: str | None = None,
    time_max: str | None = None,
    partition: dict[str, Any] | None = None,
    partition_range: dict[str, Any] | None = None,
    columns: list[str] | None = None,
    format: str = "parquet",
    max_row_groups: int | None = None,
    base_url: str | None = None,
    engine: str = "auto"
) -> pd.DataFrame | Any
```

Read the rows of a previously indexed H3 location: your team's own
index of `path`, else the public one.

The server returns a large result a page at a time; `query` follows the
pages and joins them, so the whole result is held in this process's
memory. To keep memory down, narrow the selector or time window (and fan
out across narrower queries with `fused.submit` if more than one is
needed).

At most one spatial selector may be given: `cell` (an H3 cell id, as a
hex string -- matches every row filed under a descendant of `cell`, or
under `cell` itself if it is already at the location's resolution),
`lat`+`lng` (a point), `bbox` (a `(min_lng, min_lat, max_lng, max_lat)`
tuple), or `hex_range` (an inclusive raw H3 cell-id range, as a
`(hex_min, hex_max)` tuple of hex strings). Omitting all of them returns
every row at the location.

Only space, time and partition values are filtered. Filter other columns
(a vessel type, a LiDAR class) on the returned DataFrame. A result too
large for one read raises (see Raises); split a larger area or time window
into smaller queries.

**Parameters:**

- **path** (`str`) – The location an earlier `fused.h3.index` call registered.
- **cell** (`str | None`) – An H3 cell id (as a hex string, e.g. `"8928308280fffff"`).
- **lat** (`float | None`) – Latitude of a point selector. Requires `lng`.
- **lng** (`float | None`) – Longitude of a point selector. Requires `lat`.
- **bbox** (`tuple[float, float, float, float] | None`) – `(min_lng, min_lat, max_lng, max_lat)` bounding box selector.
  A row is kept when the centre of its cell lies inside the box, so
  the edge is accurate to one cell at the location's resolution. For
  an exact edge, pad the box by one cell and filter the point columns.
- **hex_range** (`tuple[str, str] | None`) – `(hex_min, hex_max)` inclusive raw H3 cell-id range.
- **time_min** (`str | None`) – Inclusive lower bound (ISO datetime). Only valid against a
  location with a time column (a `time_column`, or a single `date`
  partition column).
- **time_max** (`str | None`) – Inclusive upper bound (ISO datetime). Only valid against a
  location with a time column.
- **partition** (`dict[str, Any] | None`) – Keep only the folders whose partition values match, as
  `{column: value}`. A list or tuple of values matches any of them:
  `{"scenario": ["ssp245", "ssp585"], "date": "2050-01"}`. A folder
  must match every column named. A `date` column matches by
  overlap: `"2050-01"` matches a folder holding January 2050.
- **partition_range** (`dict[str, Any] | None`) – Keep only the folders whose partition value lies in
  an inclusive `(min, max)` range, as `{column: (min, max)}`; `None`
  leaves an end open: `{"date": ("2050-01", None)}`. Works for
  string, number and date columns. A range on the location's time
  column also narrows the time window.
- **columns** (`list[str] | None`) – Which columns to read. Defaults to all columns.
- **format** (`str`) – `"parquet"` (the default) returns the matching rows as a
  DataFrame. `"index"` returns a read plan for Fused's own readers
  instead of rows (see Returns); it needs job2 (available inside
  Fused UDFs).
- **max_row_groups** (`int | None`) – How much of the dataset one page of the result may
  read. It sets the page size, not a limit on the result: the
  query follows the pages until every row is read. If None (the
  default), a default page size applies.
- **base_url** (`str | None`) – Base URL for the API. If None, uses the current environment.
- **engine** (`str`) – Where the rows are read and filtered. `"server"` reads them
  on Fused's servers. `"auto"` (the default) reads them in this
  process when it can, and otherwise on the server. Both return
  the same rows, though row order is not defined.

**Returns:**

- `DataFrame | Any` – A pandas DataFrame with the matching rows. With `format="index"`, a
- `DataFrame | Any` – read plan object instead, for Fused's own readers (needs job2; not a
- `DataFrame | Any` – stable interface), with the attributes `num_row_groups` and
- `DataFrame | Any` – `public`.

**Raises:**

- `ValueError` – If `engine` is unknown.
- `HTTPError` – If the API request fails (404 if `path` has not
  been indexed, 409 if it is not yet `"ready"`, if a data file changed
  after it was indexed (re-run `fused.h3.index`), or if it was
  re-indexed while the pages were being read (run the query again),
  400 for an invalid or conflicting selector, against time bounds
  on a timeless location, or for a `partition` or `partition_range`
  naming a column that is not a partition column or holding a value
  that does not fit it).

    time_max="2024-01-31T23:59:59",

## run_ingest_raster_to_h3

```python
run_ingest_raster_to_h3(
    input_path: str | list[str],
    output_path: str,
    metrics: str | list[str] = "cnt",
    res: int | None = None,
    k_ring: int = 1,
    res_offset: int = 1,
    chunk_res: int | None = None,
    file_res: int | None = None,
    overview_res: list[int] | None = None,
    overview_chunk_res: int | list[int] | None = None,
    max_rows_per_chunk: int = 0,
    include_source_url: bool = True,
    target_chunk_size: int | None = None,
    nodata: int | float | None = None,
    debug_mode: bool = False,
    remove_tmp_files: bool = True,
    tmp_path: str | None = None,
    overwrite: bool = False,
    steps: list[str] | None = None,
    extract_engine: str | None = None,
    extract_max_workers: int = 256,
    partition_engine: str | None = None,
    partition_max_workers: int = 256,
    overview_engine: str | None = None,
    overview_max_workers: int = 256,
    **kwargs: int
)
```

Run the raster to H3 ingestion process.

This process involves multiple steps:

- extract pixels values and assign to H3 cells in chunks (extract step)
- combine the chunks per partition (file) and prepare metadata (partition step)
- create the metadata `_sample` file and overviews files

**Parameters:**

- **input_path** (`str, list`) – Path(s) to the input raster data.
  When this is a single path, the file is chunked up for processing
  based on `target_chunk_size`. When this is a list of paths, each
  file is processed as one chunk.
- **output_path** (`str`) – Path for the resulting Parquet dataset.
- **metrics** (`str or list of str`) – The metrics to compute per H3 cell.
  Supported metrics are either "cnt" or a list containing any of
  "avg", "min", "max", "stddev", "mode" (i.e. most common value),
  and "sum".
- **res** (`int`) – The resolution of the H3 cells in the output data.
  The pixel values are assigned to H3 cells at resolution
  `res + res_offset` and then aggregated to `res`.
  By default, this is inferred based on the resolution of the
  input data ensuring the H3 cell size is close to the pixel size
  (e.g. for a raster with pixel size of 30x30m, a resolution of 11
  is inferred).
- **k_ring** (`int`) – The k-ring distance at resolution `res + res_offset`
  to which the pixel value is assigned (in addition to the center
  cell). Defaults to 1.
- **res_offset** (`int`) – Offset to child resolution (relative to `res`) at
  which to assign the raw pixel values to H3 cells.
- **file_res** (`int`) – The H3 resolution to chunk the resulting files of the
  Parquet dataset. By default will be inferred based on the target
  resolution `res`. You can specify `file_res=-1` to have a single
  output file.
- **chunk_res** (`int`) – The H3 resolution to chunk the row groups within
  each file of the Parquet dataset (ignored when `max_rows_per_chunk`
  is specified). By default will be inferred based on the target
  resolution `res`.
- **overview_res** (`list of int`) – The H3 resolutions for which to create
  overview files. By default, overviews are created for resolutions 3
  to 7 (or capped at a lower value if the `res` of the output dataset
  is lower).
- **overview_chunk_res** (`int or list of int`) – The H3 resolution(s) to chunk
  the row groups within each overview file of the Parquet dataset. By
  default, each overview file is chunked at the overview resolution
  minus 5 (clamped between 0 and the `res` of the output dataset).
- **max_rows_per_chunk** (`int`) – The maximum number of rows per chunk in the
  resulting data and overview files. If 0 (the default), `chunk_res`
  and `overview_chunk_res` are used to determine the chunking.
- **include_source_url** (`bool`) – If True, include a `"source_url"` column in
  the output dataset that contains a list of source URLs that
  contributed data to each H3 cell. Defaults to True, set to False
  to omit this column.
- **target_chunk_size** (`int`) – The approximate number of pixel values to
  process per chunk in the first "extract" step. Defaults to
  10,000,000 for ingesting a single file or a few files. If ingesting
  more than 20 files, each file is processed as a single chunk by
  default, but you can override this by specifying a specific
  `target_chunk_size` value, or by specifying `target_chunk_size=0` to
  always process each file as a single chunk.
- **nodata** (`int or float`) – By default, the "nodata" value indicated in the
  raster metadata will be used to ignore pixels with this value when
  ingesting the data. If this information is missing or wrong in the
  raster metadata, you can override the value by specifying this
  keyword.
- **debug_mode** (`bool`) – If True, run only the first two chunks for
  debugging purposes. Defaults to False.
- **remove_tmp_files** (`bool`) – If True, remove the temporary files after
  ingestion is complete. Defaults to True.
- **tmp_path** (`str`) – Optional path to use for the temporary files.
  If specified, the extract step is skipped and it is assumed that
  the temporary files are already present at this path.
- **overwrite** (`bool`) – If True, overwrite the output path if it already
  exists, by first removing the existing content before writing the
  new files. Defaults to False, in which case an error is raised if
  the `output_path` is not empty.
- **steps** (`list of str`) – The processing steps to run. Can include
  "extract", "partition", "metadata", and "overview". By default, all
  steps are run.
- **extract_engine** (`str`) – The engine to use for the extract step.
  By default, tries first with "realtime" and then falls back to "large".
- **extract_max_workers** (`int`) – The maximum number of workers to use for the extract step.
  Defaults to 256.
- **partition_engine** (`str`) – The engine to use for the partition step.
  By default, tries first with "realtime" and then falls back to "large".
- **partition_max_workers** (`int`) – The maximum number of workers to use for the partition step.
  Defaults to 256.
- **overview_engine** (`str`) – The engine to use for the overview step.
  By default, tries first with "realtime" and then falls back to "large".
- **overview_max_workers** (`int`) – The maximum number of workers to use for the overview step.
  Defaults to 256.

The extract, partition and overview steps are run in parallel using
[`fused.submit()`](/python-sdk/top-level-functions/#fusedsubmit). By default, the function will first attempt to run this using
"realtime" instances, and retry any failed runs using "large" instances.

You can override this behavior by specifying the `engine`, `max_workers`,
`worker_concurrency`, etc parameters as additional
keyword arguments to this function (`**kwargs`). If you want to specify
those per step, use `extract_engine`, `partition_engine`, etc.
For example, to run everything locally on the same machine where this
function runs, use:

```
run_ingest_raster_to_h3(..., engine="local")
```

## sources.era5

```python
era5(
    *,
    outputs: Sequence[str],
    month: str | None = None,
    date: str | None = None,
    cadence: str = "daily",
    bbox: Sequence[float] | None = None,
    read_workers: int = 16
) -> Source
```

Read a month or a day of ERA5 weather from the public ARCO store as lat/lng rows.

ARCO ERA5 is Google's public copy of the ECMWF ERA5 reanalysis: hourly
global weather on a 0.25 degree latitude/longitude raster, 1940 to now.
Reading needs network access to `storage.googleapis.com`. Decoding the
zarr chunks needs `numcodecs`, which the Fused runtime provides;
anywhere else, install it yourself.

The time range is the source's **input**: exactly one of `month` and
`date`. Give it here to read that range in one pass, or leave it out and
give one per part to `fused.h3.partition(..., parts=[{"month": "2024-01"}, {"month": "2024-02"}], partition_by=["month"])`.

Yields record batches with columns `lat`, `lng`, `month` (a string such
as `"2024-01"`), `date` (`date32`), `hour` (`uint8`, hourly only) and one float32 column per output, in the
order given. Longitudes are converted to `[-180, 180)` for a tidy output
column; the nearest-point fill does not need it. Cells are not computed
here: hex it with
`fused.h3.partition(..., point_column=("lat", "lng"), fill="nearest")`, which
fills every cell from its nearest raster point.

A daily call yields the range one lat/lng tile at a time (90 by 90
degrees, so 8 tiles over the globe). A tile batch holds every requested
day, day-major: one complete raster of the tile's 0.25 degree points per
`date`. Tiles are disjoint sets of raster points, so each cell is filled
from exactly one tile. Without `partition_by`, `partition` therefore
writes one monthly file per H3 parent cell directly; only parents that
straddle a tile edge are hit by two tiles and merged. `partition_by="date"`
still works and writes one folder per day instead.

An hourly call yields one batch per day (a month of hourly rasters is about
3 GB per column, too much to hold at once). A batch holds all 24 hours,
hour-major: 24 complete rasters, one per `hour` 0 to 23. Pass
`partition_by="date"` so each day becomes a folder
(`output/date=<date>/<parent>.parquet`) of one file per H3 parent cell.

This function is the template for a new datasource: any generator that
yields batches of this shape (a complete regular lat/lng raster per key
tuple, plus key and value columns) works with `partition`. `partition`
treats every column that is not floating point (`date`, `hour`) as a
key and fills the float32 outputs.

**Parameters:**

- **outputs** (`Sequence[str]`) – Output columns to read. Names depend on `cadence`: daily
  has statistics such as `t2m_min`, `t2m_max`, `t2m_mean`,
  `tp` (precipitation, mm) and `ssrd` (radiation, W/m2); hourly
  has one column per variable such as `t2m` and `tp`.
- **month** (`str | None`) – Input. One month as `"YYYY-MM"`.
- **date** (`str | None`) – Input. One day as `"YYYY-MM-DD"`. Give this or `month`.
- **cadence** (`str`) – `"daily"` reduces each day's hours to one row per point per
  day and yields the range in lat/lng tiles. `"hourly"` keeps every
  hour (24 times the rows) in one batch per day and reads one day at a
  time to bound memory.
- **bbox** (`Sequence[float] | None`) – `(min_lng, min_lat, max_lng, max_lat)` in degrees, longitude in
  `[-180, 180]`, to keep only the raster points inside the box
  (edges inclusive). `min_lng > max_lng` means the box crosses the
  antimeridian. Default `None` reads the whole globe. The store's
  chunks hold the whole globe per hour, so `bbox` saves memory and
  output, not download. Cells emitted by `partition` are those
  whose nearest raster point is in the box. The box must keep at
  least two latitude rows and two longitude columns (span at least
  two 0.25 degree points on each axis).
- **read_workers** (`int`) – Concurrent chunk downloads.

**Raises:**

- `ValueError` – Unknown `cadence` or `outputs`, a `month` or `date`
  that is not valid text of its form, both of them given, or a
  `bbox` that is malformed, out of range, selects no raster
  point, or spans fewer than two points on an axis. Iterating
  without either of `month` and `date` raises too.
- `Era5SourceError` – Raised during iteration, not at the call, when the
  ARCO store cannot be read or `numcodecs` is missing.

**Example:**

```python
from fused import h3
h3.partition(
    h3.sources.era5(outputs=["t2m_mean", "tp"]),
    "fd://me/era5/",
    parts=[{"month": "2024-01"}, {"month": "2024-02"}],
    partition_by=["month"],
    point_column=("lat", "lng"), fill="nearest", h3_res=7,
    file_res=1, read_engine="large",
)  # doctest: +SKIP

# Hourly takes the same call with a ``date`` per part and
# ``partition_by=["date"]``; each day's file holds all 24 hours.

h3.partition(
    h3.sources.era5(outputs=["t2m"], cadence="hourly"),
    "fd://me/era5_hourly/",
    parts=[{"date": "2024-01-01"}, {"date": "2024-01-02"}],
    partition_by=["date"],
    point_column=("lat", "lng"), fill="nearest", h3_res=7,
    file_res=1,
)  # doctest: +SKIP
```

## sources.parquet

```python
parquet(
    path: str | Path,
    *,
    columns: Sequence[str] | None = None,
    batch_size: int | None = 65536,
    **hive_keys: Any
) -> Source
```

Stream a parquet file, or every `.parquet` file under a folder.

Files are read in sorted path order. `path` can be a local path or any
fsspec URL (`fd://`, `file://`, `s3://`, `gs://`, `az://`, `memory://`).
Remote schemes need their fsspec backend installed (s3fs, gcsfs, adlfs).

**Parameters:**

- **path** (`str | Path`) – A parquet file or a folder of them (searched recursively).
- **columns** (`Sequence[str] | None`) – Read only these columns. Default is all columns.
- **batch_size** (`int | None`) – Maximum rows per yielded batch. `None` yields each
  parquet row group as one batch, however large.
- \*\***hive_keys** (`Any`) – The subfolder to read, as hive keys: `year=2020` reads
  `<path>/year=2020/`, and several keys nest in the order given
  (`year=2020, month=1` reads `<path>/year=2020/month=1/`). Each
  key is added to every batch as a constant string column when the
  files lack it (hive writers leave it out of the files). With
  `fused.h3.partition(..., parts=[{"year": 2020}, ...])` each
  dict is one part. `path`, `columns` and `batch_size` cannot
  be hive keys.

Nothing is listed or opened until the first batch is read, so a source
over remote storage can be described (and sent to the Fused server) without
storage credentials.

**Raises:**

- `ValueError` – A hive key or value is not a plain name or scalar. Also
  raised on the first iteration, not at the call, when no parquet
  files were found.

## sources.table

```python
table(data: Any) -> Iterator[pa.RecordBatch]
```

Yield the batches of a `pandas.DataFrame`, `pyarrow.Table` or
`pyarrow.RecordBatch`.

A DataFrame index becomes a column only when every level is named;
otherwise (a `RangeIndex` or an unnamed index, such as after filtering)
it is dropped. A `geopandas.GeoDataFrame`'s geometry columns arrive as
WKB (`binary`), the form `fused.h3.partition(..., point_column=...)`
expects; GeoParquet read with `parquet` is already WKB. The centroid
is planar in the coordinates as stored (lon/lat degrees expected), so
geometries that cross the antimeridian or wrap a pole are mis-hexed;
split them or pass lat/lng columns as `point_column=` for those rows.

**Raises:**

- `TypeError` – `data` is none of those.
