# H3 Data Retrieval on Fused

Use `fused.h3` to make a large geospatial dataset fast to query: **partition** it into H3 Parquet files, **index** it, then **query** any area, point, H3 cell, time window or partition value, from a UDF running on Fused or over HTTP with `GET /h3/query`. Every call runs on the user's own Fused account. Never call a canvas share link from code: it runs as the canvas owner.

Each snippet says what to expect. Numbers come from live data, so they can differ a little. Check the shape and columns first.

References: https://docs.fused.io/rest-api/h3 (every REST parameter and error), https://docs.fused.io/python-sdk/api-reference/h3 (`fused.h3`), https://docs.fused.io/widget-api/fused-map (the map widget).

## Set up

```bash
pip install -U "fused[vector]" h3
fused login          # opens the browser; check with `fused whoami`
```

`fd://` is the user's own Fused storage. `s3://` and `gs://` work too if the account can reach the bucket.

## 1. Partition

`partition` takes a **source**, not a DataFrame: passing a DataFrame raises `TypeError`. A source is one of:

- `fused.h3.sources.udf(my_udf)`: a UDF that returns the rows. Use this for data you have in Python.
- `fused.h3.sources.era5(outputs=[...], date=..., bbox=...)`: ERA5 weather, with `fill="nearest"`.
- A folder path on `fd://`, `s3://` or `gs://`, or `fused.h3.sources.parquet(path)`: Parquet already in storage.

The work runs on Fused batch jobs. `partition` returns a run at once; `run.tail()` streams its logs until it finishes, and `run.wait()` does the same silently.

```python
import fused


@fused.udf
def nyc311_day(date: str = "2024-07-04"):
    import pandas as pd
    from urllib.parse import urlencode

    query = urlencode({
        "$select": "unique_key, created_date, complaint_type, borough, latitude, longitude",
        "$where": f"created_date between '{date}T00:00:00' and '{date}T23:59:59' AND latitude IS NOT NULL",
        "$limit": 100000,
    })
    df = pd.read_csv(f"https://data.cityofnewyork.us/resource/erm2-nwe9.csv?{query}")
    df["date"] = date
    return df


path = "fd://h3_examples/nyc311_one_day/"
run = fused.h3.partition(
    fused.h3.sources.udf(nyc311_day),
    path,
    point_column=("latitude", "longitude"),
    h3_res=11,
    partition_by="date",
)
run.tail()
```

Expect `nyc311_day()` to return 10,492 rows with columns `unique_key`, `created_date`, `complaint_type`, `borough`, `latitude`, `longitude`, `date`. `partition` prints `fused.h3.partition: started run grp:... (1 job) into s3://...`; `run.tail()` takes about 2 minutes, then `run.status()` is `'succeeded'`.

How rows get a cell. Pass exactly one of `point_column` and `hex_column`; data with both a cell column and a geometry needs only `hex_column`, and the geometry stays in the files:

- Latitude and longitude: `point_column=("lat", "lon")`, in degrees (EPSG:4326). Projected coordinates raise.
- A WKB geometry column, such as building polygons: `point_column="geometry"`. Each row gets the cell of its centroid; nothing is polyfilled. A GeoDataFrame returned by a source UDF arrives as WKB.
- An H3 cell column (uint64) with any name: `hex_column="my_cells"`. The cells are kept as they are and `h3_res` does not change them. The output column is always `hex`.

Other parameters and best practices:

- `h3_res` (default 7): the resolution of each row's cell, which queries select by. Set it yourself from the size of your features: https://docs.fused.io/guide/h3-analytics/resolution-guide. Res 11, about 25 m across, fits buildings and street-level points.
- `file_res` (default 1): the parent cell that groups rows into one file. Raise it for more, smaller files, so a query reads less.
- `partition_by`: nonspatial columns such as `date` or `scenario`, never location. Each value becomes a `col=value` folder, so values must not be null or empty, contain `/` or start with `_`. Pick the column queries filter on, and avoid one where a single value holds most rows: a query for it still reads almost every file. A column name, or a list of them, takes the folders from the data in one job; a dict splits the run into one job per value (next section).
- `engine`: `"small"` (the default, 2 vCPUs, 2 GB), `"medium"` (16 vCPUs, 64 GB) or `"large"` (64 vCPUs, 512 GB), all batch jobs with no time limit. `"realtime"` starts at once but stops after 2 minutes, so it suits only small Parquet sources; a UDF source raises with it.
- Running again: with column names in `partition_by`, every run reads the source again and replaces the folders it writes; all other folders stay. With a dict `partition_by` (next section), jobs already done are skipped. Without `partition_by`, a run into an existing output raises, and `redo=True` replaces it. To change `h3_res`, `file_res`, `fill`, `sort_by` or the partition columns, write to a new output path; a run whose settings differ from the existing output raises.
- `options`: tuning as a dict, such as `{"row_group_size": 65536, "workers": 4}`. An unknown key raises.
- Old code still works for one release and warns. `parts=` is now `partition_by`, `force=` and `refresh=` are `redo=True`, `append=` can go (a rerun merges), `only=` means passing only those values, and the one-by-one tuning arguments go in `options`. `overwrite=` has no replacement: write to a new output path, since `redo=True` never clears old folders.

### Many days: one job per value

Give the source UDF a parameter and pass its values as `partition_by={"date": [...]}`. Each value becomes one job, bound to the UDF's `date` parameter, and the jobs run in parallel.

```python
import fused
import pandas as pd

days = pd.date_range("2024-07-04", "2024-07-05").strftime("%Y-%m-%d")
run = fused.h3.partition(
    fused.h3.sources.udf(nyc311_day),
    "fd://h3_examples/nyc311_days/",
    point_column=("latitude", "longitude"),
    h3_res=11,
    partition_by={"date": days},
)
run.tail()
```

Expect `started run grp:... (2 jobs)`, with jobs `date=2024-07-04` and `date=2024-07-05`, about 2 minutes. Rules:

- Each key must be a column the source returns (`date` here). Otherwise the job fails with `... returned no 'date' column; partition keys must be output columns`.
- `run.errors()` only says `Batch job ... ended with status Failed`; `run.tail()` prints the cause. `run.retry()` runs the failed jobs again and leaves the others alone.
- Running again skips jobs that are already done, so adding a day costs one job. `redo=True` reads those jobs again and rewrites them.
- A list of dicts, such as `[{"date": "2024-07-04"}, {"date": "2024-07-05"}]`, is an explicit job list. Every dict needs the same keys.
- A run started elsewhere (for example inside a UDF that returned `run.id`): `fused.h3.get_run(run_id).status()`.
- Adding data later: partition again with the new values, then index only the new folders with `fused.h3.index("fd://h3_examples/nyc311_days/", subset={"date": "2024-07-06"}).tail()`.

## 2. Index

```python
fused.h3.index(path).tail()
status = fused.h3.index_status(path)
```

Expect `index` to take a few seconds. `status` is a dict: `status` `'ready'`, `visibility` `'team'`, `files` 1, `resolution` 11, `hex_column` `'hex'`, `partition_columns` `[{'name': 'date', 'type': 'string', 'distinct': 1, 'min': '2024-07-04', 'max': '2024-07-04'}]`, plus `time_min`, `time_max`, `row_groups`, `failures`. Query before the run finishes and you get `This location is still 'indexing'`. For a timestamp column inside the files, pass `time_column="name"`. Index again whenever the files change.

- `engine`: the default `"realtime"` stops after 2 minutes. When a run times out, pass a batch instance with no time limit: `"small"` (2 vCPUs, 2 GB), `"medium"` (16 vCPUs, 64 GB) or `"large"` (64 vCPUs, 512 GB).
- New data: run index again. It indexes only new, changed and removed files and skips unchanged folders. On a large dataset, pass `subset={"date": "2024-07-06"}` (a value or a list of them) so index lists only those folders; the keys must be the leading partition columns.
- `redo=True` reads files again: with `subset`, only the files in those folders; without it, the whole tree from scratch, which is also how to change the dataset's columns.
- Index after every partition. A query that reaches a file changed after indexing fails with HTTP 409 until you index again.
- Without partition, every Parquet file must have an integer H3 cell column at one resolution; name it with `hex_column` if it is not `hex`.
- Old code: `prefix=` (use `subset=`), `overwrite=` and `force=` (use `redo=True`) and `workers=` (use `options={"workers": ...}`) still work and warn. `delete_index` and `indexed_files` still take `prefix=`, a folder.

`index_status` also works on a public dataset you did not build. Expect `fused.h3.index_status("s3://fused-asset/data/nyc311/")` to give `files` 1923, `resolution` 11, `partition_columns` `[{'name': 'month', 'type': 'string', 'distinct': 192, 'min': '2010-01', 'max': '2025-12'}]`, `time_min` `'2010-01-01T00:00:00'`.

### List or remove indexed files

```python
files = list(fused.h3.indexed_files(path))
fused.h3.delete_index(path, prefix="date=2024-07-04")
fused.h3.index(path).tail()
```

Expect `files` to hold one path ending in `date=2024-07-04/812a3ffffffffff.parquet`. `delete_index` with `prefix` drops only that folder from the index and returns `count` 1 and `folders` 1. The Parquet files stay, and `index_status` shows `files` 0 until the last line indexes the folder again. Without `prefix` the whole index is deleted.

## 3. Query

`fused.h3.query` runs only inside a UDF on Fused. Called anywhere else, it raises `RuntimeError: fused.h3.query only runs inside a Fused UDF on a realtime or batch instance`. Wrap it in a UDF and run that with `fused.run`:

```python
@fused.udf
def nyc311_area(path: str, date: str = "2024-07-04"):
    import fused

    return fused.h3.query(path, bbox=(-74.02, 40.70, -73.93, 40.80), partition={"date": date})


df = fused.run(nyc311_area, path=path)
```

Expect a DataFrame, 1,312 rows: the source columns plus `hex` (uint64 H3 cell). Give at most one spatial selector:

| Selector | Example | Rows here |
|---|---|---|
| `bbox=(min_lng, min_lat, max_lng, max_lat)` | above | 1,312 |
| `cell=` a coarser or equal cell, as a hex string | `cell="872a10088ffffff"` | 67 |
| `lat=`, `lng=` | a point | the rows in that cell |
| `hex_range=(min, max)` | two hex strings | every row between them |

Narrow further with `time_min`/`time_max` (ISO strings), `partition={...}`, `partition_range={"date": ["2024-07-01", "2024-07-07"]}` and `columns=[...]`. Only the named columns come back, so list `"hex"` in `columns` when you need the cell. A query matches whole cells: for an exact edge, pad the box by about one cell and filter by latitude and longitude. The whole result is held in the UDF's memory, so a result too large fails the job: split the area or time window, and run the smaller queries in parallel with `fused.submit`. Only place, time and partition values are filtered: filter other columns, such as a category, on the returned DataFrame. Always give a place; with none, the whole dataset comes back.

## Query over HTTP

Every indexed dataset is also served by `GET https://www.fused.io/server/v1/h3/query`, the way to read it from outside a UDF. A dataset gets this endpoint only once it is indexed. The response is Parquet. Every parameter and error: https://docs.fused.io/rest-api/h3.

```bash
curl -G "https://www.fused.io/server/v1/h3/query" \
  --data-urlencode "path=s3://fused-asset/data/nyc311/" \
  -d min_lng=-73.990 -d min_lat=40.750 -d max_lng=-73.980 -d max_lat=40.758 \
  --data-urlencode 'partition={"month": "2025-12"}' \
  -d columns=hex -d columns=complaint_type \
  -o nyc311.parquet
```

Expect HTTP 200 and 752 rows with columns `hex`, `complaint_type`.

- **Selectors:** the same as `fused.h3.query`, as URL parameters: a box (`min_lng`, `min_lat`, `max_lng`, `max_lat`), `lat` and `lng`, `cell`, or `hex_min` and `hex_max`. Narrow with `time_min`/`time_max`, `partition` and `partition_range` (JSON objects), and repeat `columns=` per column.
- **Credentials:** a public `s3://` dataset needs none. For the user's own dataset add `-H "Authorization: Bearer $FUSED_ACCESS_TOKEN"` with a token from `fused.api.access_token()`; without it the endpoint returns 403.
- **Paging:** when more rows remain, the response has an `X-Fused-Next-Cursor` header. Send it back as `cursor=` with the same query until there is none.
- **Errors:** the body is JSON with a `detail` message. Read it, fix the request, then retry.
- **Browser:** the endpoint allows cross-origin requests, so a web page can `fetch` it and parse the Parquet, for example with hyparquet.

## Visualize with the `fused-map` widget

In a Workbench canvas, a `fused-map` widget draws H3 cells as hexagons. Full props: https://docs.fused.io/widget-api/fused-map. Guide: https://docs.fused.io/guide/h3-analytics/visualization.

### From a UDF: `h3` layer

A UDF queries the dataset and returns one row per cell; the widget draws the result. Save the UDF as `nyc311_hexes`, the widget as a JSON-UI node, and add the edge `["nyc311_hexes", "hex_map"]` in `canvas.toml`.

```python
import fused


@fused.udf
def udf(month: str = "2025-12"):
    df = fused.h3.query(
        "s3://fused-asset/data/nyc311/",
        bbox=(-73.990, 40.750, -73.980, 40.758),
        partition={"month": month},
        columns=["hex", "complaint_type"],
    )
    return df.groupby("hex", as_index=False).size().rename(columns={"size": "count"})
```

```json
{
  "type": "fused-map",
  "props": {
    "layers": [
      {
        "id": "nyc311_hexes",
        "name": "NYC 311, December 2025",
        "udf": "{{nyc311_hexes}}",
        "type": "h3",
        "h3Column": "hex",
        "tooltip": true,
        "legend": true,
        "style": {
          "fillColor": {"type": "continuous", "attr": "count", "palette": "OrYel", "domain": [0, 40]},
          "opacity": 0.8
        }
      }
    ]
  }
}
```

Expect the UDF to return 167 rows with columns `hex`, `count`, and the map to fly to Midtown with 167 hexagons coloured by `count` and a legend from 0 to 40. `{{nyc311_hexes?month=$month}}` lets a `dropdown` with `"param": "month"` in the same widget change the month.

### Straight from `/h3/query`: `fused-hex` layer

No UDF: the widget sends one `/h3/query` request per map tile. `type` must be set, it is never detected.

```json
{
  "type": "fused-map",
  "props": {
    "basemap": "mapbox://styles/mapbox/dark-v11",
    "centerLng": -73.985,
    "centerLat": 40.754,
    "zoom": 14,
    "layers": [
      {
        "id": "nyc311_rest",
        "name": "NYC 311, December 2025",
        "type": "fused-hex",
        "h3Column": "hex",
        "source": {
          "path": "s3://fused-asset/data/nyc311/",
          "timeColumn": "created_date",
          "dateMin": "2025-12-01",
          "dateMax": "2025-12-31T23:59:59",
          "variables": ["year"],
          "reduce": "sum"
        },
        "tooltip": ["hex", "count"],
        "legend": {"title": "311 requests"},
        "style": {
          "fillColor": {"type": "continuous", "attr": "count", "palette": "Sunset", "domain": [0, 40]},
          "opacity": 0.8
        }
      }
    ]
  }
}
```

Expect hexagons over all of Midtown at zoom 14, coloured by `count`. `reduce: "sum"` collapses each cell's rows in the window to one row and adds `count`, `date_min` and `date_max`; `variables` names the columns to fetch, so keep it to one small column. `source.path` sets the endpoint to `/h3/query`; add `"endpoint": "https://www.fused.io/server/v1/h3/query"` to call another server.

## In a Workbench canvas

Split the steps into UDFs: a source UDF, a partition UDF that calls `fused.h3.sources.udf(fused.load("source_udf_name"))` and returns `run.id`, an index UDF, and a query UDF. Best practices for each step and a worked example: https://docs.fused.io/guide/h3-analytics/data-retrieval-end-to-end.

## Scale up

- Large reads: `read_engine="large"`. Partition running out of memory: set `options={"workers": 2}`; 2 to 4 works.
- Hundreds of GB or tens of thousands of files: contact info@fused.io.
